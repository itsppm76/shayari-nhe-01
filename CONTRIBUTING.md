## ⟩ What's Out of Scope Here

- **Source code contributions** — the Shayari NHE-01 engine is closed-source and maintained privately. This repository doesn't build or deploy anything.
- **Security or privacy vulnerabilities** — do **not** file these as a public issue. See [SECURITY.md](./SECURITY.md) for responsible disclosure.
- **Account-specific or billing support** — use the in-app support channel, not this repository.

## ⟩ How to Contribute

**For bug reports and small fixes:**
1. Search [existing issues](../../issues) first — someone may have already reported it.
2. Open a new issue using the appropriate template.
3. Be specific. "The website is broken" helps nobody; "the pricing page 404s on mobile Safari as of [date]" does.

**For documentation changes:**
1. Fork this repository.
2. Create a branch: `docs/short-description`.
3. Make your change, keeping the existing formatting style (see below).
4. Open a pull request with a clear description of what changed and why.

**For governance or feature proposals:**
1. Open a [discussion](../../discussions) first — this is a conversation, not a submission.
2. Be prepared to explain the reasoning, not just the ask. Governance changes especially are evaluated against the checks in [GOVERNANCE.md § What Governance Review Actually Checks](./GOVERNANCE.md#-what-governance-review-actually-checks).

## ⟩ Documentation Style

If you're editing a Markdown file in this repository, please keep the visual language consistent:

- Section headers use `⟩` or `✦` prefixes, not plain `##` alone
- Tables over prose lists where a comparison is being made
- No unexplained jargon — this repo is public-facing; assume the reader is smart but not necessarily technical
- Badges via [shields.io](https://shields.io), `style=for-the-badge`, dark `labelColor`
- Keep code fences for genuine code/diagrams only — don't wrap prose in them for decoration
