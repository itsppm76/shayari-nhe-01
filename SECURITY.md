## ⟩ Please Read Before Anything Else

**Do not open a public GitHub issue for a security or privacy vulnerability.** This repository is public, and a public issue is a public disclosure — please give us the chance to fix it first.

Shayari NHE-01 handles personal conversation data, much of it emotionally sensitive by nature. We take that seriously, and we take reports about it seriously.

<br/>

---

## ⟩ What to Report Here

- Any way to access another user's conversations, memories, images, or account data
- Any way to bypass authentication or impersonate another user
- Any way to circumvent the crisis-response system or make it fail to trigger when it should
- Any way to make Shayari NHE-01 perform facial recognition, biometric matching, or otherwise identify a specific person from an image — this is a permanent governance boundary (see [GOVERNANCE.md](./GOVERNANCE.md)), and any way to defeat it is treated as a security issue, not a feature request
- Any way to extract another user's private data through prompt manipulation
- Any vulnerability in the public website or its infrastructure
- Evidence that a governance commitment described in [GOVERNANCE.md](./GOVERNANCE.md) is not actually being honored in the live product

<br/>

## ⟩ What's Out of Scope

- Vulnerabilities in third-party services we integrate with but don't control (report those to the third party directly)
- Issues requiring physical access to a user's device
- Social engineering attacks against project maintainers or staff
- Rate-limiting/quota bypass that doesn't expose any data (report as a normal bug instead)

## ⟩ How to Report

<table>
<tr>
<td width="50%" valign="top">

### 🔐 Preferred: GitHub Private Vulnerability Reporting
If this repository has [Private Vulnerability Reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability) enabled, use the **Security** tab → **Report a vulnerability**. </td>
<td width="50%" valign="top">

### 📧 Alternative: Direct Contact
If private reporting isn't available, contact the project maintainers directly through the channel listed on the official Writistic Studios / OpenNHE website. Please include "SECURITY" in the subject line.

</td>
</tr>
</table>

**In your report, please include:**
- A clear description of the vulnerability and its potential impact
- Steps to reproduce (as specific as possible)
- Any proof-of-concept, screenshots, or logs that help us understand it
- Whether you'd like credit for the discovery, and how you'd like to be named (or to remain anonymous)

## ⟩ What Happens Next

```
  Report received
        │
        ▼
  Acknowledgement, typically within a few business days
        │
        ▼
  Investigation & severity assessment
        │
        ▼
  Fix developed & deployed (timeline depends on severity)
        │
        ▼
  Confirmation back to you, and — with your permission — public credit
```

We ask that you give us reasonable time to investigate and remediate before any public disclosure. In turn, we commit to keeping you informed of progress and to crediting your work (unless you prefer otherwise).

<br/>

---

## ⟩ A Note on Good-Faith Research

We will not pursue legal action against security researchers who:
- Make a good-faith effort to avoid privacy violations, data destruction, or service disruption while investigating
- Only interact with accounts they own or have explicit permission to test
- Give us the opportunity to fix an issue before any public disclosure
- Don't exploit a vulnerability beyond what's necessary to demonstrate it
